# SketchUp 建築自動建模軟體 — 全面分析與架構設計

> 版本：v0.1（分析階段）
> 文件目的：在動手寫程式之前，先把「要做什麼、為什麼、怎麼做」完整界定清楚，作為後續開發的藍圖。

---

## 0. 一句話定位

> **一套以參數驅動（parametric）的 SketchUp 外掛，輸入一組建築立面/帷幕牆參數，即可自動生成符合工法細部的 3D 模型，並支援版本迭代、前後比對與出圖。**

對應你提供的三張圖：

| 你的素材 | 對應到系統的哪一塊 |
|---|---|
| 參數對照表（舊版/新版：鰭片數量、間距、寬度、深度、立面寬度、顏色、鏡頭方位） | **參數資料模型 + 版本/迭代比對功能** |
| SketchUp 截圖（垂直鰭片 + 玻璃帷幕 + 樓板） | **自動建模引擎的輸出成果** |
| 建築剖面細部圖（CW-01 / GL-01 / W-02 / W-03 / RC 樓板 / 結構樑 / 防水落水） | **構件庫（Component Library）與工法細部規則** |

## 1. 專案目標與範疇

### 1.1 核心目標
1. **自動化重複勞動**：手動拉 13 支鰭片、對齊間距、貼材質非常耗時且易錯。系統一鍵生成。
2. **參數可調**：所有尺寸（立面寬度、開間數、鰭片數量/間距/寬度/深度、玻璃分割、樓層高、樓板厚…）皆為可調參數，改數字即重建。
3. **工法正確性**：生成的模型符合建築細部邏輯（帷幕牆單元、玻璃、收邊、樓板、結構樑、防水落水），而不只是「看起來像」。
4. **迭代與比對**：保存每一版參數（如圖中的「舊版 vs 新版」），可一鍵切換、並排比較、輸出對照表。
5. **可出圖出表**：自動套用鏡頭方位（如 30°）、材質、場景（Scene），導出圖面與 BOM 數量表。

### 1.2 範疇邊界（MVP 先做什麼、不做什麼）

| 範疇 | MVP（第一階段） | 後續階段 |
|---|---|---|
| 建築類型 | 單一立面（帷幕牆 + 垂直遮陽鰭片 + 樓板） | 多立面、整棟、樓梯、屋頂 |
| 構件 | 鰭片、豎框/橫框、玻璃單元、樓板、結構樑 | 陽台欄杆、防水落水細部、室內天花 |
| 細部層級 | LOD 200–300（量體 + 主要構件） | LOD 400（含收邊、五金、防水層） |
| 平台 | SketchUp 桌面版（Ruby API） | 雲端參數服務 / 報表後台 |

## 2. 需求分析

### 2.1 功能性需求（Functional）

- **F1 參數輸入面板**：以表單輸入所有設計參數，含單位（英吋/公分/公釐切換）。
- **F2 即時/一鍵建模**：按下生成 → 在 SketchUp 中產生完整模型（純 Component/Group 結構，不汙染現有場景）。
- **F3 參數重建**：改任一參數可「就地更新」既有模型（刪除舊群組、重建），避免手動清理。
- **F4 構件庫**：內建可重用的 Component（鰭片、玻璃、框料、樓板…），支援使用者自訂尺寸。
- **F5 材質/顏色**：套用材質（如鰭片「深鐵灰」、玻璃半透明藍），可由參數指定。
- **F6 版本管理**：儲存多組參數為「方案（Scheme）」，命名、切換、刪除。
- **F7 方案比對**：並排或疊圖比較兩方案，自動產生對照表（就是你那張表）。
- **F8 鏡頭/場景**：依參數設定相機方位角（如 30°）、建立 Scene、一鍵套用。
- **F9 數量統計（BOM）**：自動統計鰭片支數、玻璃面積、框料長度等，導出 CSV。
- **F10 匯入/匯出參數**：參數以 JSON 儲存，可分享、版控、批次跑。

### 2.2 非功能性需求（Non-functional）

- **效能**：生成數百個構件時 < 數秒；大量實例用 ComponentInstance 共用定義，降低面數。
- **穩定**：所有建模包在單一 `model.start_operation / commit_operation`，可單步 Undo。
- **可維護**：幾何生成、參數模型、UI 三層分離，方便擴充新構件。
- **可移植**：相容 SketchUp 2021+（HtmlDialog 為主）；單位內部一律走 SketchUp 原生（英吋）。
- **可測試**：幾何運算與參數驗證可獨立於 UI 進行單元測試。

### 2.3 使用者故事（節錄）

- 身為設計師，我想把「立面寬度 144"、3 個開間、13 支鰭片、間距 12"、寬 2.5"、深 10"」一鍵生成，以便快速看量體。
- 身為設計師，我想把「舊版（12 支/間距 8"/寬 0.5"）」與「新版」並排比較，以便向業主說明改善。
- 身為設計師，我想把鏡頭設成 30° 正面角度自動出圖，以便每版都有一致的呈現。

## 3. 技術選型

### 3.1 為什麼是 SketchUp Ruby API
SketchUp 官方且唯一的自動建模管道就是 **Ruby API**（外掛 Extension）。它能：
- 程式化建立點/線/面、`pushpull` 擠出量體
- 建立 `ComponentDefinition` 並大量 `instance`（省記憶體、可一改全改）
- 套用 `Material`、建立 `Scene/Page`、控制 `Camera`
- 用 `UI::HtmlDialog` 建立現代化 HTML/JS 介面與 Ruby 後端雙向通訊

### 3.2 技術棧

| 層 | 技術 |
|---|---|
| 建模核心 | Ruby（SketchUp Ruby API） |
| UI 前端 | `UI::HtmlDialog` + HTML / CSS / JavaScript |
| 前後端通訊 | `dialog.add_action_callback` / `sketchup.callback`（JSON 字串） |
| 參數儲存 | JSON 檔（方案庫）；可選 `model.set_attribute` 存進 .skp |
| 打包發佈 | `.rbz`（SketchUp Extension 安裝包） |
| 測試 | TestUp / minitest（幾何與參數層） |

### 3.3 關鍵設計慣例
- **單位**：API 內部以英吋計，你的表格本來就用英吋（8"、12"、2.5"…），天作之合。輸入層做單位轉換。
- **不破壞使用者場景**：所有產出包進一個頂層 Group/Component（例如 `[AutoFacade]`），重建只動這個群組。
- **共用定義**：同尺寸鰭片只建一個 `ComponentDefinition`，其餘為 `instance` → 面數低、改一處全部更新。

## 5. 參數資料模型（系統的核心）

把你那張對照表「正規化」成機器可讀的 Schema。每個參數都有：鍵、單位、預設、範圍、說明。

### 5.1 立面與格網
| 鍵 | 說明 | 單位 | 範例（新版） | 範圍 |
|---|---|---|---|---|
| `elevation_width` | 立面總寬度 | in | 144 | 24–600 |
| `bay_count` | 開間數 | 個 | 3 | 1–10 |
| `floor_height` | 樓層高 | in | 144 | 96–240 |
| `floor_count` | 樓層數 | 個 | 3 | 1–60 |

### 5.2 垂直遮陽鰭片 (W-02)
| 鍵 | 說明 | 單位 | 舊版 | 新版 |
|---|---|---|---|---|
| `fin_count` | 鰭片數量 | 支 | 12 | 13 |
| `fin_spacing` | 鰭片間距 | in | 8 | 12 |
| `fin_width` | 鰭片寬度（面外厚） | in | 0.5 | 2.5 |
| `fin_depth` | 鰭片深度（出挑） | in | 8 | 10 |
| `fin_color` | 鰭片顏色 | hex | 淺灰 | 深鐵灰 |
| `fin_layout` | 排列方式 | enum | by_count / by_spacing | — |

> 註：`fin_count` 與 `fin_spacing` 在固定 `elevation_width` 下會互相牽動。系統需提供
> 「鎖定數量算間距」或「鎖定間距算數量」兩種模式（`fin_layout`），避免衝突——這正是
> 舊版「太密」問題的根因（間距 8" 配 12 支塞滿 96" 立面）。

### 5.3 帷幕牆 / 玻璃 (CW-01 / GL-01)
| 鍵 | 說明 | 單位 |
|---|---|---|
| `panel_width` | 玻璃單元寬 | in |
| `mullion_width` / `mullion_depth` | 豎框斷面 | in |
| `glass_color` / `glass_opacity` | 玻璃色 / 透明度 | hex / 0–1 |

### 5.4 結構 (RB-01 / B-01)
| 鍵 | 說明 | 單位 |
|---|---|---|
| `slab_thickness` | 樓板厚 | in |
| `slab_overhang` | 樓板出挑 | in |
| `beam_width` / `beam_depth` | 樑斷面 | in |

### 5.5 呈現
| 鍵 | 說明 | 範例 |
|---|---|---|
| `camera_azimuth` | 鏡頭方位角 | 30° |
| `camera_height` / `fov` | 視點高 / 視角 | — |

### 5.6 方案（版本）JSON 範例
```jsonc
{
  "scheme_name": "新版（修正）",
  "created": "2026-06-07",
  "units": "inch",
  "elevation": { "width": 144, "bay_count": 3, "floor_height": 144, "floor_count": 3 },
  "fins": { "count": 13, "spacing": 12, "width": 2.5, "depth": 10,
            "color": "#3a3f44", "layout": "by_count" },
  "curtain_wall": { "panel_width": 36, "mullion_width": 2, "mullion_depth": 5,
                    "glass_color": "#bcd8e6", "glass_opacity": 0.35 },
  "structure": { "slab_thickness": 8, "slab_overhang": 24,
                 "beam_width": 12, "beam_depth": 24 },
  "view": { "camera_azimuth": 30, "fov": 35 }
}
```

## 6. 建模引擎流程

```
generate(params):
  1. validate(params)                 # 範圍/相依性檢查（數量 vs 間距）
  2. model.start_operation("AutoFacade")
  3. root = 取得或新建頂層群組 [AutoFacade]；清空舊內容
  4. grid = Grid.compute(params)      # 算出每層 Z、每支鰭片 X、每片玻璃位置
  5. for each floor:
        Slab.build(grid, params)      # 樓板
        Beam.build(grid, params)      # 結構樑
        CurtainWall.build(grid, params)  # 框料 + 玻璃單元（用共用 Component）
  6. Fin.build_array(grid, params)    # 沿 X 陣列鰭片（共用 Component instance）
  7. Materials.apply(root, params)    # 深鐵灰 / 玻璃藍
  8. Camera.apply(params); Scene.create
  9. model.commit_operation
 10. report = Report.bom(root)        # 回傳數量供 UI 顯示
```

**幾何要點**
- 鰭片：建一片矩形面 `fin_width × fin_depth` → `pushpull` 樓高 → 存成 Component → 沿 X 以 `fin_spacing` 陣列 `instance`。
- 玻璃：薄板面 + 半透明材質；框料為細長量體沿格網邊生成。
- 樓板/樑：矩形 `pushpull`，依 `slab_overhang` 出挑。
- 全程用 `Geom::Transformation` 定位，定義只建一次。

## 9. 風險與對策

| 風險 | 影響 | 對策 |
|---|---|---|
| 參數相依衝突（數量×間距 ≠ 立面寬度） | 模型超出邊界或太密 | 兩種佈局模式 + 即時驗證（本案舊版主因） |
| 面數爆炸 | 卡頓 | 共用 ComponentDefinition + instance |
| 破壞使用者既有場景 | 資料遺失 | 全部包進專屬頂層群組；重建只動它 |
| 單位混亂 | 尺寸錯誤 | 內部一律英吋，輸入層轉換 |
| SketchUp 版本差異 | 介面壞掉 | 以 HtmlDialog 為主、宣告最低支援版本 |
| 工法正確性不足 | 不能用於施工 | 構件庫對照剖面圖（CW/GL/W/RB/B 編碼）逐步補細部 |
