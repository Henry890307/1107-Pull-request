## 1. Wan 2.2 概覽：I2V 與 T2V 差異

Wan 2.2 是阿里巴巴通義萬象團隊開發的開源影片生成模型，支援兩種生成模式：

### T2V（Text-to-Video，文字生影片）

- **輸入**：文字提示詞
- **用途**：從零開始生成影片場景
- **特點**：構圖自由度高，適合創作全新場景
- **模型**：`Wan2.2-T2V-14B`

### I2V（Image-to-Video，圖片生影片）

- **輸入**：文字提示詞 + 起始圖片
- **用途**：讓靜態圖像產生動態效果
- **特點**：可精確控制起始幀的畫面內容
- **模型**：`Wan2.2-I2V-14B`
- **應用**：FLUX 生圖後接 Wan I2V 讓圖片動起來

### 兩者的工作流差異

| 比較項目 | T2V | I2V |
|---|---|---|
| 輸入 | 純文字提示詞 | 提示詞 + 起始圖片 |
| VRAM 消耗 | 較低（無 image encoder）| 較高（需 image encoder）|
| 構圖控制 | 完全由提示詞決定 | 起始幀固定第一畫面 |
| 動態程度 | 通常動作較大 | 起始幀固定，動作較受控 |
| 常見用途 | 場景創作 | 靜態圖轉動圖 |

## 2. 14B 雙模型兩階段取樣原理

Wan 2.2 的 14B 版本採用「雙模型兩階段（High-noise + Low-noise）」取樣策略，這是提高影片品質與一致性的關鍵技術。

### 兩階段原理

```
第一階段：High-noise Model（高噪音模型）
  ├─ 負責生成影片的整體結構、運動軌跡、場景布局
  ├─ 在高噪音步驟（早期去噪）發揮作用
  └─ 決定影片的「大框架」

        ↓ 傳遞中間 latent

第二階段：Low-noise Model（低噪音模型）
  ├─ 負責細化影片的紋理、細節、銳利度
  ├─ 在低噪音步驟（後期去噪）發揮作用
  └─ 決定影片的「精細品質」
```

### 為什麼使用兩個模型？

14B 模型拆成高噪音與低噪音兩個版本，是因為：
1. **特化分工**：各階段需要不同的去噪能力，專業化模型品質更好
2. **記憶體效率**：兩個模型可以交替載入 VRAM，避免同時佔用過多記憶體
3. **品質提升**：相比單一模型，兩階段取樣在動態一致性和畫面品質上均有改善

### 節點實作（ComfyUI-WanVideoWrapper）

```
第一階段（High-noise）：
[WanModelLoader: Wan2.2-I2V-14B-High-Noise]
        ↓
[WanVideoSampler]
  steps: 20（第一階段）
  cfg: 3.5
  sigmas: [noise_range_high → noise_range_mid]
        ↓ latent（中間結果）

第二階段（Low-noise）：
[WanModelLoader: Wan2.2-I2V-14B-Low-Noise]
        ↓
[WanVideoSampler]
  steps: 20（第二階段）
  cfg: 3.5
  latent: (來自第一階段輸出)
  sigmas: [noise_range_mid → 0]
        ↓

[WanVideoDecoder / VAEDecodeVideo]
        ↓
[VHS Video Combine] → 輸出影片
```

## 3. 模型檔案放置位置

### 主要模型（diffusion_models/）

```
ComfyUI/models/diffusion_models/
├── Wan2.2-T2V-14B-High-Noise/       ← T2V 高噪音模型（目錄）
│   ├── diffusion_pytorch_model.safetensors（可能分片）
│   └── config.json
├── Wan2.2-T2V-14B-Low-Noise/        ← T2V 低噪音模型（目錄）
├── Wan2.2-I2V-14B-High-Noise/       ← I2V 高噪音模型（目錄）
└── Wan2.2-I2V-14B-Low-Noise/        ← I2V 低噪音模型（目錄）
```

### Text Encoder（clip/）

```
ComfyUI/models/clip/
└── umt5-xxl-enc-bf16.safetensors    ← UMT5 XXL 文字編碼器（Wan 專用）
```

> 注意：Wan 使用 **UMT5**（非 FLUX 的 T5 XXL），兩者不可混用。

### VAE（vae/）

```
ComfyUI/models/vae/
└── wan_2.1_vae.safetensors          ← Wan VAE（向後相容 2.1/2.2）
```

> Wan 2.2 的 VAE 與 Wan 2.1 相同，已有 Wan 2.1 VAE 者無需重新下載。

### 總磁碟空間需求

| 元件 | 大小 |
|---|---|
| T2V 14B（高+低噪音）| ~55 GB |
| I2V 14B（高+低噪音）| ~55 GB |
| UMT5 XXL Encoder | ~9 GB |
| Wan VAE | ~3 GB |
| **合計（T2V + I2V）** | **~122 GB** |

## 4. 解析度與 Frame 數設定

### 建議解析度

Wan 2.2 在以下解析度下有最佳品質（訓練解析度）：

| 比例 | 解析度（T2V）| 解析度（I2V）| 備註 |
|---|---|---|---|
| 1:1 | 480 x 480 | 480 x 480 | 方形 |
| 16:9 | 832 x 480 | 832 x 480 | 橫幅（推薦）|
| 9:16 | 480 x 832 | 480 x 832 | 直幅（手機）|
| 4:3 | 640 x 480 | 640 x 480 | 傳統比例 |

> 解析度偏離訓練值（如 1024x576）可能導致畫面扭曲或品質下降。

### Frame 數與影片長度

Wan 2.2 以 **16fps** 播放為標準計算：

| Frame 數 | 影片長度（16fps）| VRAM 需求（fp16）| 生成時間（約）|
|---|---|---|---|
| 17f | ~1 秒 | ~14 GB | ~90s |
| 33f | ~2 秒 | ~18 GB | ~160s |
| 49f | ~3 秒 | ~22 GB | ~240s |
| 65f | ~4 秒 | ~26 GB | ~320s |
| 81f | ~5 秒 | ~30 GB | ~400s |
| 97f | ~6 秒 | >32 GB（可能 OOM）| - |

> **RTX 4080 32GB 穩定極限約為 81 frames（5 秒）**。更多 frames 需使用 fp8 或降低解析度。

### Frame 數必須是 4n+1 形式

Wan 2.2 的 frame 數需符合 `4n+1` 的格式：17、21、25、33、37、41、49、53、57、65、69、73、81…

## 5. 誠實說明：單次可生成的影片長度

### 直接說明

**單次生成無法超過約 5~6 秒**（81 frames），這不是軟體限制，而是 VRAM 物理限制。

即使在 32GB VRAM 的 RTX 4080 上：
- 81 frames（5 秒）= 約 30 GB VRAM（fp16，可行但緊張）
- 97 frames（6 秒）= >32 GB VRAM（fp16，通常 OOM）
- 200+ frames（60 秒）= 完全不可行

**因此，生成 60 秒或 120 秒影片的唯一實際方式是：分段生成 + 串接**。

## 6. 長影片製作：分段生成與串接流程

### 總體策略

```
[場景規劃] → 將 60 秒影片拆成 12 段，每段約 5 秒
      ↓
[第 1 段生成] → 5 秒影片（81 frames）
      ↓
[取第 1 段最後一幀] → 作為第 2 段的 I2V 起始圖
      ↓
[第 2 段生成（I2V）] → 5 秒影片（81 frames）
      ↓
[重複以上步驟 12 次]
      ↓
[使用 VHS / 影片剪輯軟體串接所有片段]
      ↓
[60 秒完整影片]
```

### 步驟一：規劃分段腳本

建議在生成前規劃每段的提示詞，確保場景連貫：

```
第 1 段：A woman walks into a coffee shop, slow pan shot, cinematic
第 2 段：She sits down at a table by the window, same woman, same clothing
第 3 段：She orders coffee from the barista, continuous shot
...
```

### 步驟二：取最後一幀（Last Frame）

在 ComfyUI 中取得最後一幀：

```
[VHS Load Video] → 載入第 1 段影片
        ↓
[VHS Get Frames] → 取得所有幀
        ↓
[Image Batch to List] → 列表形式
        ↓
[List Index: -1] → 取最後一幀（索引 -1）
        ↓
[SaveImage] → 儲存為起始圖
```

或使用 `KJNodes` 的 `GetImageFromBatch` 節點更便捷。

### 步驟三：用 Last Frame 做 I2V 接續

```
[Load Image: 上一段最後一幀]
        ↓
[WanVideoWrapper I2V 工作流]
  提示詞：延續上一段的場景描述
  denoise: 0.9~1.0（高去噪讓動作自然延續）
  strength of first frame: 0.9（保持畫面連續性）
        ↓
[下一段 5 秒影片]
```

### 步驟四：串接影片片段

**方法 A：使用 VHS（ComfyUI-VideoHelperSuite）**

```
[VHS Video Combine]
  images: [所有段落的幀列表（Batch）]
  frame_rate: 16
  format: video/h264-mp4
        ↓
[輸出完整影片]
```

**方法 B：使用外部影片剪輯軟體**

1. 將每段影片匯出為 MP4
2. 使用 DaVinci Resolve（免費）、Premiere Pro 或 CapCut 串接
3. 在剪接點使用「交叉溶解」轉場（約 2~3 幀）可隱藏段落銜接處的輕微跳躍

### 段落銜接注意事項

1. **提示詞連貫性**：相鄰段落的提示詞應有重疊描述（如角色外觀、場景光線）
2. **種子一致性**：在測試階段可固定 seed 以確保風格一致
3. **Last Frame 品質**：若最後一幀因動態模糊而模糊，往前取幾幀（-2 或 -3）
4. **銜接點處理**：使用 1~3 幀的交叉溶解可有效遮蓋段落接縫

## 7. fp16 vs fp8 取捨

### fp16（預設）

- **VRAM 佔用**：14B 模型 ~27 GB（高噪音或低噪音，一次只載一個）
- **品質**：最佳
- **適用**：81 frames 以內，解析度 832x480 以下
- **設定**：WanModelLoader weight_dtype = `default` 或 `fp16`

### fp8（量化）

- **VRAM 佔用**：14B 模型 ~14 GB
- **品質**：輕微差異，動態細節略有損失
- **適用**：需要生成更多 frames 或更高解析度時
- **設定**：WanModelLoader weight_dtype = `fp8_e4m3fn`

### 本工作站建議

| 情境 | 建議精度 |
|---|---|
| 81f，480p，標準生成 | fp16 |
| 97f+ 嘗試 | fp8 |
| 同時使用多個工具（ControlNet 等）| fp8 |
| 最終高品質輸出 | fp16 |

## 8. CFG 與步數設定

### CFG（Classifier-Free Guidance）

Wan 2.2 使用傳統的 CFG（有正面和負面提示詞）：

| CFG 值 | 效果 |
|---|---|
| 1.5~2.5 | 低引導，影片更自然流動但可能偏離提示詞 |
| 3.0~4.0 | 標準引導，平衡品質與提示詞符合度（**推薦**）|
| 5.0~7.0 | 高引導，嚴格跟隨提示詞，可能動作稍僵 |

**建議值**：`CFG = 3.5`（兩個階段使用相同 CFG）

### 步數設定（兩階段各自的步數）

| 步數分配 | 品質 | 生成時間 | 適用 |
|---|---|---|---|
| 第一階段 15 步 + 第二階段 15 步 | 良好 | 較快 | 快速預覽 |
| 第一階段 20 步 + 第二階段 20 步 | 優良 | 中等（**推薦**）| 日常生成 |
| 第一階段 25 步 + 第二階段 25 步 | 最佳 | 較慢 | 最終輸出 |

**建議**：兩階段各 20 步（合計 40 步），在品質與時間上最均衡。

### 負面提示詞建議

```
low quality, blurry, inconsistent motion, flickering, duplicate frames,
watermark, text overlay, distorted faces, bad anatomy
```

## 9. 32GB VRAM 效能與降載技巧

### 預期效能（RTX 4080 32GB，fp16）

| 設定 | VRAM 消耗 | 每段生成時間（81f, 832x480）|
|---|---|---|
| fp16，兩階段各 20 步 | ~28~30 GB | ~7~10 分鐘/段 |
| fp8，兩階段各 20 步 | ~16~20 GB | ~5~7 分鐘/段 |
| fp8，兩階段各 15 步 | ~16~20 GB | ~4~5 分鐘/段 |

> 生成一段 5 秒影片約需 7~10 分鐘；60 秒影片（12 段）約需 1.5~2 小時。這是本地 14B 模型的正常速度。

### 降載技巧（依情況選擇）

**方法一：使用 fp8 模型**
```
WanModelLoader: weight_dtype = fp8_e4m3fn
```
節省約 12~14 GB VRAM，允許更多 frames 或更高解析度。

**方法二：降低解析度**

從 832x480 降至 640x480（節省約 15% VRAM），品質影響較小。

**方法三：降低 Frame 數**

- 81f（5 秒）→ 65f（4 秒），每段節省約 4 GB VRAM
- 適合 VRAM 在 26~28 GB 時使用

**方法四：使用 CPU Offload（最後手段）**

啟動 ComfyUI 時加入：
```bat
python main.py --lowvram
```
會大量使用系統 RAM（96GB 可容納），但速度會大幅降低（3~5 倍慢）。

**方法五：UMT5 使用 CPU 模式**

將 UMT5 Encoder 設定為在 CPU 上執行（犧牲 text encoding 速度換取 VRAM）：
```
在 WanVideoWrapper 節點設定 text_encoder_device = cpu
```

## 10. 常見錯誤與排除

### OOM（Out of Memory）錯誤

**錯誤訊息**：`RuntimeError: CUDA out of memory`

| 解法 | 具體操作 |
|---|---|
| 切換 fp8 | UNETLoader weight_dtype = `fp8_e4m3fn` |
| 降低解析度 | 從 832x480 降至 640x480 或 480x480 |
| 降低 frames | 從 81f 降至 65f 或 49f |
| 重啟 ComfyUI | 清除 VRAM 殘留 |
| 加 `--lowvram` 啟動 | 最後手段，速度大幅下降 |
| 關閉其他 GPU 程式 | 確認 `nvidia-smi` 無其他程式佔用 VRAM |

### 影片閃爍（Flickering）

**現象**：生成的影片幀與幀之間亮度或色彩跳動

| 原因 | 解法 |
|---|---|
| CFG 過高 | 降至 3.0~4.0 |
| steps 過少（低質量 latent）| 增加至 20+20 步 |
| 使用了不相容的 VAE | 確認使用 `wan_2.1_vae.safetensors` |
| 解析度與訓練不符 | 使用 480p 系列標準解析度 |

若輕微閃爍可後處理：使用影片剪輯軟體的「去閃爍」濾鏡（DaVinci Resolve 有內建）。

### 動作不足（影片幾乎靜止）

**現象**：生成結果幾乎是靜止畫面，缺乏動態

| 原因 | 解法 |
|---|---|
| 提示詞缺少動作描述 | 加入動作詞（walking, flowing, swaying, moving）|
| CFG 過高壓制動態 | 降至 3.0~3.5 |
| I2V 起始圖 weight 過高 | 降低 image condition strength（如設 0.85）|
| 使用 T2V 模型做 I2V | 確認使用對應的 I2V 模型 |

**動作豐富的提示詞技巧**：
```
dynamic motion, camera slowly panning left, leaves gently swaying in the wind,
cinematic movement, flowing hair, rippling water
```

### 模型找不到 / 節點錯誤

| 現象 | 解法 |
|---|---|
| WanModelLoader 無法找到模型 | 確認模型放在 `diffusion_models/` 下的正確子目錄 |
| UMT5 找不到 | 確認 `umt5-xxl-enc-bf16.safetensors` 在 `models/clip/` 下 |
| VAE 載入錯誤 | 確認 `wan_2.1_vae.safetensors` 在 `models/vae/` 下 |
| ComfyUI-WanVideoWrapper 紅框 | Manager → Update Custom Nodes → 重啟 |

### VHS 輸出無聲音

Wan 2.2 生成的影片本身無聲音。若需要音訊：
1. 在影片剪輯軟體（DaVinci Resolve、Premiere Pro）中添加背景音樂
2. 使用 AI 配音工具（ElevenLabs 等）生成語音
